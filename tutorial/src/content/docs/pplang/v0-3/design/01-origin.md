pplang 的起点不是“再设计一套语法”，而是一个更具体的问题：学完编程语言、编译器、数据库、操作系统、网络与计算机体系结构之后，怎样确认自己真的理解了？

pp-labs 选择把知识落成四个项目：

| 项目 | 要回答的问题 | 主要理论来源 |
|---|---|---|
| pplang | 一门小型系统语言应该保留什么、拒绝什么 | TAPL、PLAI、语言工程实践 |
| pplc | 源码怎样成为有类型的机器代码 | 龙书、TAPL、CSAPP |
| ppdb | 页、记录、索引和事务怎样组成数据库 | Database System Concepts |
| ppos | 软件怎样从启动走到网络与应用 | OSTEP、组成原理、Kurose & Ross、CSAPP |

这四个项目不是四份互不相关的作业。pplc 实现 pplang；ppdb 和 ppos 使用 pplang；真实数据库和操作系统代码又持续暴露语言与编译器的问题。

## 从“知道”到“做出来”

书本会给出普遍模型：

- TAPL 用判断规则描述一个表达式何时具有某种类型。
- PLAI 通过构造解释器和语言逐步理解语义。
- CSAPP 解释值如何成为位、地址、调用和目标文件。
- 组成原理解释处理器、内存和 IO 为什么要求特定表示。

但工程会继续追问：

- `if` 是否接受整数，错误应该在哪一层拒绝？
- 字符串只是地址，还是地址与长度绑定的视图？
- 一个值可能是整数或文本时，怎样防止 tag 与 payload 失配？
- 泛型需要比较能力时，是隐式查找实现，还是显式传函数？
- 同一份代码如何既链接 libc，又在没有操作系统的环境运行？

pplang 就是在回答这些问题的过程中形成的。它不是对某本书的逐章实现，而是理论、工程约束和作者判断的交点。

## 三个目标必须同时成立

### 能教

读者应当能够从 token、AST、类型检查一直追到 LLVM IR。一个语言机制如果必须先理解宏展开、隐式候选搜索或庞大运行时，便不适合作为这条教学主线的基础。

### 能写系统软件

语言不能只计算表达式。pp 必须表达字节、地址、内存布局、外部函数、volatile 访问和函数指针，并生成目标文件与 freestanding 产物。

### 能被工具稳定理解

人和 LLM 都更容易处理局部、显式的约束。显式泛型实参、严格 bool、有限的模式匹配和窄 FFI，使错误更早出现，也减少依赖隐藏上下文的推理。

## 真实项目怎样反向塑造语言

ppdb 的 SQL 值最初依靠手写整数 tag。tag 与 payload 没有类型联系，促成了 enum 和穷尽 switch。

ppos 的网络、TLS 与文件系统反复处理二进制缓冲。NUL 结尾字符串无法可靠表示这些数据，促成 `str = {ptr,len}` 和切片边界检查。

标准库、数据库和协议代码出现“算法相同、元素类型不同”的重复，促成 v0.3 显式泛型；而比较、哈希和分配仍通过函数指针传入，没有引入 trait solver。

因此，pplang 的方法不是先收集 feature，而是：

```text
真实重复或风险
      ↓
提炼最小机制
      ↓
写入规范和编译器
      ↓
回到 ppdb / ppos 验证
```

:::tip[观察与理论的关系]
书本告诉我们有哪些成熟模型；项目告诉我们当前真的需要哪一部分；设计者负责决定停止线。pplang 的价值就在这个选择过程，而不在语法新奇。
:::
