## v0.1：打通最小闭环

最初目标是让 `.pp` 真正经过手写 lexer、递归下降 parser 和 LLVM codegen，生成可执行程序。变量、函数、控制流、struct、extern 和裸机输出构成第一条闭环。

这个阶段证明“能编译”，但语言语义仍接近宽松的 C：整数可能冒充条件，作用域和无符号运算存在债务，字符串边界不统一。

## v0.2：先还语义债务

v0.2 没有先追求大语法，而是收紧基础语义：

- 无符号除法、余数和比较使用正确 LLVM 指令。
- `if`/`while` 只接受 bool。
- block 建立真正的词法作用域。
- `str` 统一为 `{ptr,len}`，切片进行边界检查。
- 旧数组语法被正式移除。
- tuple、解构、指针接收者自动取址进入语言。
- `Buf` 与 `StrMap` 进入标准库。
- enum 与穷尽 switch 消除手写 tag。

这一阶段的关键词是“可信”：规范承诺的语义必须由编译器和测试兑现。

## v0.3：受约束的类型复用

真实代码已经证明泛型有价值，但 pp 不希望因此引入一整套 trait/interface 世界。v0.3 采用显式实例化和 AST 单态化：

```pp
fn identity[T](value: T) -> T { return value; }

let answer: int = identity[int](42);
```

泛型 struct、enum、嵌套实例、`sizeof[T]()` 与 `alignof[T]()` 一并落地。泛型体不能直接对未知 `T` 做算术或比较，所需能力必须成为参数。

## v0.3 的冻结含义

冻结并不表示实现永远不修，而是语义表面不再漂移：v0.3.x 可以修 bug、补诊断和澄清规范；新增语法或破坏兼容性的行为必须进入下一个语言版本。
