语言设计不仅由加入什么定义，也由拒绝什么定义。v0.3 的停止线同时服务于教学可理解性、编译器规模和系统工程需要。

| 不提供 | 为什么停下 | v0.3 的替代方式 |
|---|---|---|
| GC | 隐藏运行时和回收时机，不适合裸机主线 | 显式 allocator、`defer`、arena/池 |
| borrow checker | 会让切片教学先依赖所有权证明 | `{ptr,len}` 信息绑定 + 生命周期契约 |
| trait/interface | 引入实现查找、约束求解和更复杂诊断 | 函数指针显式传递能力 |
| 泛型推导 | 实例类型依赖更多上下文 | 所有类型实参显式写出 |
| comptime/宏 | 显著扩大编译期语言表面 | `sizeof/alignof` 等窄 builtin |
| `unsafe {}` | 当前没有权限系统改变块内外规则 | 裸指针类型、builtin 与模块边界 |
| 源码级 asm | 目标相关且难以保持教学稳定 | compiler builtin 与 C/汇编胶水 |
| `?*T` | 为单一情况增加新类型规则 | 判空或 `Option[*T]` |
| 异常/async | 隐藏控制流和运行时状态 | Result enum、显式协程库 |
| 包管理器 | 不属于 v0.3 语言语义 | 相对路径 import；工具链另行设计 |

## “没有”不等于“不重要”

Rust 的所有权、Zig 的 comptime、Go 的 interface 和 C++ 的模板都在各自目标中成立。pplang 不是在评判这些机制，而是在选择一条能从源码追到 LLVM IR、再进入数据库和操作系统的较短路径。

同样，v0.3 不保证内存安全。裸指针可以悬垂，allocator 可以泄漏，extern 声明可以写错 ABI。课程会明确说明责任，不会用“小语言”掩盖风险。

## 四层能力边界

遇到新需求时，先判断它属于哪一层：

| 层 | 例子 | 判断标准 |
|---|---|---|
| 核心语言 | enum、泛型、词法作用域 | 改变所有程序的语义模型 |
| 标准库 | Buf、Vec、StrMap、allocator | 可以用现有语言机制实现 |
| compiler builtin | volatile、端口 IO、地址转换 | 需要 LLVM 或目标机器能力 |
| C/汇编胶水 | 启动、上下文切换、第三方库适配 | ABI 复杂或高度目标相关 |

这个分层保护语言不会因为接入 uIP、BearSSL 或某个设备驱动而不断增加专用语法。

:::caution[少机制必须更可靠]
边界不能成为行为不一致的借口。pplang 既然提供无符号整数、切片、Sum Type 和泛型，就必须完整兑现它们的类型、边界和代码生成语义。
:::
