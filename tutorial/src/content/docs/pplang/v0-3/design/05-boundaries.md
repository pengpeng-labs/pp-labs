语言设计不仅由加入什么定义，也由拒绝什么定义。v0.3 的停止线是教学模型和实现成本的一部分。

| 不提供 | 原因 | pp 的替代方式 |
|---|---|---|
| GC | 隐藏运行时与回收时机，不适合裸机主线 | 显式 allocator、`defer`、arena |
| borrow checker | 会让切片和指针教学先依赖所有权证明 | `{ptr,len}` 信息绑定与生命周期约定 |
| trait/interface | 引入实现查找、约束求解与更复杂诊断 | 函数指针显式传能力 |
| 泛型推导 | 调用含义依赖更多上下文 | 所有类型实参显式写出 |
| `comptime`/宏 | 编译期语言会显著扩大语义表面 | `sizeof/alignof` 等窄 builtin |
| `unsafe {}` | 如果内部没有权限检查，它只是装饰 | 裸指针类型、builtin 与模块边界 |
| 源码级 `asm` | 目标相关且难以保持教学稳定 | compiler builtin 与 C/汇编胶水 |
| `?*T` | 为单一场景增加新类型规则 | 判空或 `Option[*T]` |
| 异常/async | 隐藏控制流和运行时状态 | 返回 Sum Type、显式协程库 |

这些都不是对其他语言的价值判断。Rust 的所有权、Zig 的 comptime 和 C++ 的模板各自在自己的目标里成立；pp 只是选择一个更小、可以从源码追到机器边界的教学闭环。

:::caution[边界不是借口]
少机制不能成为行为不一致的理由。pp 既然提供无符号整数、切片、Sum Type 和泛型，就必须完整兑现这些机制的语义保证。
:::
