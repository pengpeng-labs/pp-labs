## 1. 机制少，但必须完整

pp 偏好能组合的机制，而不是为每个场景增加语法。函数指针既能做回调，也能表达泛型所需的比较、哈希和分配能力；struct 方法只是普通函数调用的语法糖；Sum Type 只提供构造、单层解构和穷尽性。

“少”不等于残缺。既然提供 Sum Type，穷尽检查就不能省；既然 `str` 声称带长度，stdlib 就不能退回 NUL 扫描；既然有无符号类型，比较、除法和余数就必须遵守无符号语义。

## 2. 显式优先于聪明

泛型调用写成 `choose[int](...)`。编译器不猜类型实参，也不为 `T` 自动寻找运算符实现。程序需要比较能力，就接收一个 `fn(T,T)->bool`。

这会多写几个字符，却让调用点、模板依赖和编译结果都可以局部理解。

## 3. 用信息绑定约束内存

pp 必须有裸指针，但普通业务代码不应把所有数据都表示成裸指针。

- `str` 把地址与长度绑定。
- `Buf`/`Vec[T]` 把地址、长度和容量绑定。
- `defer` 把清理动作与函数退出绑定。
- enum 把状态 tag 与合法 payload 绑定。

pp 不证明所有权，也不隐藏释放责任。它提供比 C 更多的信息，同时避免引入 borrow checker。

## 4. 由 ppdb 和 ppos 验证

一个语言特性只有在至少一个真实问题中减少风险或重复，才值得进入语言。纯粹为了语法新奇而加入的功能，不符合 pp 的路线。

因此 v0.3 明确停在一个克制的位置：有 Sum Type 和显式泛型，但没有 trait、类型集合、推导、specialization、宏或 comptime。
